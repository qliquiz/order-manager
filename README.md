# Order Manager

#### Сервис для управления заказами.

---

## Технологический стек

- **Язык:** Go
- **База данных:** PostgreSQL + Redis (кеш)
- **API:** gRPC, HTTP (gRPC-Gateway)
- **Контейнеризация:** Docker, Docker Compose
- **Сборка и управление:** Makefile

## Запуск и настройка

Приложение спроектировано для запуска через Docker Compose, что является рекомендуемым способом. Также поддерживается локальный запуск для удобства разработки.

### Предварительные требования

- **Docker** и **Docker Compose** (для основного способа запуска)
- **Go** (версия 1.21+) (для локальной разработки)
- **Make** (для использования команд-ярлыков)
- **protoc** (для генерации кода из `.proto` файлов)

---

### 1. Конфигурация

Вся конфигурация проекта осуществляется через переменные окружения.

1.  Создайте файл `.env` в корне проекта, скопировав пример:
    ```bash
    cp docker.env .env
    ```
2.  Откройте файл `.env` и при необходимости измените значения.

**Пример файла `.env`:**
```env
ENV=local # Среда выполнения (local, dev, prod)
GRPC_PORT=8081 # порт сервера
GRPC_TIMEOUT=5s
GATEWAY_PORT=8080 # порт HTTP-шлюза

POSTGRES_HOST=db
POSTGRES_PORT=5432
POSTGRES_DB=lms_orders
POSTGRES_USER=postgres
POSTGRES_PASSWORD=mysecretpassword

REDIS_HOST=redis
REDIS_PORT=6379
REDIS_PASSWORD=redis
```
**Важно:** Значение `POSTGRES_HOST` отличается для запуска в Docker (`db`) и локально (`localhost`).

---

### 2. Запуск через Docker (Рекомендуемый способ)

Этот способ поднимает все необходимые сервисы (приложение, базу данных, мигратор) в изолированном Docker-окружении.

1.  Убедитесь, что в вашем `.env` файле установлено `POSTGRES_HOST=db`.
2.  Запустите все сервисы с помощью одной команды:
    ```bash
    make compose
    ```
    Эта команда соберет Docker-образы, запустит контейнеры, применит миграции базы данных и запустит приложение.

Сервис будет доступен по HTTP на порту, указанному в `GATEWAY_PORT` (например, `http://localhost:8080`).

---

### 3. Локальный запуск для разработки (Альтернативный способ)

Этот гибридный подход позволяет запускать базу данных в Docker, а само Go-приложение — напрямую на вашей машине. Это удобно для отладки.

1. **Измените `.env` файл** для локального подключения:
    ```env
    POSTGRES_HOST=localhost
    ```
2. **Запустите приложение** с помощью `make`:
    ```bash
    make run-with-db-in-docker
    ```
    Эта команда сначала применит миграции, а затем соберет и запустит бинарный файл вашего приложения.

Так же можно создать БД **локально**, чтобы совсем обойтись **без Docker**.

В таком случае – **после настройки `.env` файла** используйте следующий **ярлык**:
```bash
make run
```

### Взаимодействие с API

После запуска сервис доступен по gRPC и HTTP.

#### Пример HTTP-запроса (через cURL)

Создание нового заказа:
```bash
curl -X POST http://localhost:8080/v1/orders \
-H "Content-Type: application/json" \
-d '{"item": "Cookies", "quantity": 5}'
```

#### Пример gRPC-запроса (через grpcurl)

Предварительно установите `grpcurl`.

Создание нового заказа:
```bash
grpcurl -plaintext -d '{"item": "DVD", "quantity": 2}' \
localhost:8081 api.OrderService/CreateOrder
```

## Команды Makefile

Проект содержит `Makefile` для автоматизации рутинных задач.

- `make compose`: Запускает все сервисы (приложение, БД) через Docker Compose в фоновом режиме.
- `make run`: Применяет миграции и запускает приложение локально (требует локально запущенной БД).
- `make run-with-db-in-docker`: Запускает приложение с БД в Docker.
- `make db`: Запускает БД в Docker.
- `make build`: Собирает бинарный файл приложения (`order-manager`) в папку `./bin`.
- `make proto`: Генерирует Go-код из `.proto` файлов в папку `gen/api`.
- `make migrate-up`: Применяет все доступные миграции базы данных.
- `make migrate-down`: Откатывает последнюю примененную миграцию.
- `make lint`: Запускает линтер по проекту.
- `make clean`: Удаляет сгенерированные файлы и бинарники.
